# Диалоги «Порта» — концепт правки (19.09.2026)

Черновик решения после разговора с автором. Диалоги сами тут не пишутся —
это задел под другую модель (не тратим токены здесь), но формат вывода
описан внизу, чтобы написанное встало в данные без переделки.

## Что не устраивает сейчас

1. **Чувствительные темы доступны с первой секунды знакомства.** Пример,
   пойманный автором: «долги дома» можно спросить у любого человека сразу,
   хотя по смыслу это не тот вопрос, который задают едва познакомившись.
2. **Разговор плоский.** Тема → один ответ → тема закрыта. Продолжения
   («сказал — ответили — сказал ещё») почти не используются, хотя
   механизм для них уже есть в движке.
3. **Ровно три тона на каждую тему** (прямо / мягко / деньгами) —
   формально удобно программировать, но не всегда осмысленно: есть темы,
   где вариантов ответа игрока по смыслу должно быть 1, 2, 4 — и не «тон
   одного и того же», а содержательно разные реплики.

Матчасть (коротко): жанрово это ближе всего к «Hub and Spoke» — центральный
набор тем, к которым возвращаются в любом порядке (как в Disco Elysium) —
и это нормальный, рабочий паттерн для игры именно про «узнай и расспроси».
Проблема не в паттерне, а в деталях: доступ к темам принято завязывать на
доверие/отношения, а не только на факт «слышал», а глубина (продолжения)
должна расти там, где тема того стоит — не автоматически на 243 варианта.

## Решение — три части, разной цены

### A. Порог отношений на тему (дёшево, правка движка, общая для всей игры)

У темы (в реестре города или у конкретного человека в месте) — необязательное
поле, например `видноОт: N` (по умолчанию 0 — видно сразу, как сейчас).
Пока `распол(человек) < N`, тема **не показывается в списке** этому человеку
вообще — не серая недоступная кнопка, а просто не в списке, чтобы не дразнить
тем, чего пока нет. Расти распол уже умеет (эффект `распол` в ответах) —
тут ничего чинить не надо, только читать порог при построении списка тем.

Конкретно для «долги дома»: предлагаю `видноОт: 1` или `2` — но это на вкус
автора, я просто добавляю параметр и подставляю то число, что скажут.

### B. Первая встреча — знакомство, а не допрос (дёшево, правка движка)

Технически уже наполовину есть: `вступление` человека показывается один раз
до первого вопроса. Не хватает одного шага: на **первой встрече** список тем
вообще не показывать полностью — только 1–2 «вежливых» варианта
(что-то вроде текущего `ni_o_chem`/представиться). Весь список тем —
начиная со второй встречи. Условие «первая встреча» техническое: у этого
человека ещё нет ни одной спрошенной темы и распол = 0.

### C. Больше «дальше» (чистый контент, механизм уже в движке)

`узел.дальше` — массив шагов, каждый со своим текстом/эффектом/темой —
уже реализован и используется (тема `nakolki` у Сиба). Ничего в движке
доделывать не нужно, просто писать больше тем с продолжением — **не для
всех**, только где тема заслуживает глубины (это оценка автора/писателя
диалогов, не формальное правило).

### D. Контекстные варианты вместо тона — пилот на одном человеке

Самая дорогая часть, поэтому — только пилот, только один собеседник (первый
кандидат — Сиб), остальные пока остаются на прежней системе тонов, пока
пилот не подтверждён и не понравился.

Формат узла меняется с фиксированного:
```js
{ прямо: { т: "...", э: {...} }, мягко: { т: "...", э: {...} }, деньгами: { т: "...", э: {...} } }
```
на список нужного количества вариантов, каждый — как обычное действие
(своё условие видимости: деньги, распол, предмет — та же мини-язык
условий, что уже есть в движке):
```js
{
  свободныеВарианты: [
    { id: 'прямо', текст: "Реплика игрока", т: "Ответ", э: {...} },
    { id: 'подкол', текст: "Другая реплика — не тон, а другой смысл", условие: {...}, т: "...", э: {...}, дальше: [...] },
    // столько, сколько нужно по смыслу — 1, 2, 4, не обязательно 3
  ],
}
```
Движок при показе темы этому человеку рисует не три кнопки тона, а список
`свободныеВарианты` узла (с проверкой условий каждого варианта — тот же
механизм, что уже фильтрует кнопки по деньгам/предметам/расположению
везде в игре). У остальных людей (Ола, Ния и т.д.) ничего не меняется —
поле `свободныеВарианты` есть только там, где оно написано, иначе работает
старая система тонов. Это значит: пилот не ломает остальную игру и легко
откатывается, если не понравится.

## Формат для написания диалогов в другой модели

Памятка/промт для модели, которая будет писать сами тексты:

- **Кто персонаж**: имя, характер, манера речи, что любит/что задевает
  (`движок/данные/места/синий-час.js`, `ЛЮДИ[id]`).
- **Какие темы ему можно задать**: список тем с их содержанием/ценностью
  (`ТЕМЫ`/`РЕЕСТР`), плюс порог `видноОт`, если тема чувствительная.
- **Правило первой встречи**: на неё — только знакомство/1–2 общих
  варианта, не сразу личное.
- **Правило количества вариантов**: столько ответов игрока, сколько нужно
  по смыслу разговора, не обязательно 3, не обязательно «тон».
- **Правило глубины**: часть тем (не все) — с продолжением на 1–3 шага,
  если тема того стоит; конец ветки помечать.
- **Формат вывода** — тот блок `свободныеВарианты`, что выше, валидный
  JS-объект, ключи и структура совпадают с уже существующими данными
  (`т` — текст ответа, `э` — эффект: `распол`/`тема`/`гроши`/`флаг` и т.п.,
  та же мини-грамматика, что описана в шапке
  `данные/места/синий-час.js`).

## Что делаю я по этому плану (когда текст будет готов)

1. Добавляю в движок порог `видноОт` (A) — небольшая, общая правка.
2. Добавляю «первая встреча — только знакомство» (B) — небольшая, общая правка.
3. Добавляю в движок поддержку `свободныеВарианты` (D) — пилот, включается
   по человеку, не трогает остальных.
4. Дальше — просто подставляю присланный текст в данные, прогоняю тесты.

Сами реплики (контент) в этом заходе не писал — ждём текста от другой
модели по формату выше.
