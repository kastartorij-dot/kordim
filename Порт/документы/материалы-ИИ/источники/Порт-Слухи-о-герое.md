# Порт — концепт и задание: Слухи о герое

Написано 20.09.2026. Не входит ни в один из этапов §22 — отдельная,
самостоятельная механика, дешевле «Дел»: один новый файл-реестр, две точки
входа в уже существующий код, ни одной новой шкалы.

## Идея в одну строку

Сейчас слухи текут в одну сторону: город рассказывает герою о городе. Здесь —
обратное течение: то, что герой уже сделал, начинает опережать его самого.
Первая встреча с новым человеком — не всегда чистый лист.

## Решающее правило — уже есть в ГДД, просто не для этого

§10 ГДД, «Правило для реплик»: **текст ориентируется на факт, а не на
число** — не `if (репутация >= 2)`, а «Одвин помог моему брату». Это правило
уже написано для другого случая, но оно ровно про эту механику: слух о герое
должен по возможности называть **что** он сделал, а не сообщать общим текстом
«у тебя высокая тень». Числа (тень, фракции, распол) — резерв на случай, когда
конкретного факта ещё не случилось, не основа.

Отсюда — форма реестра ниже: у записи есть либо конкретное условие-факт
(дело завершено определённым образом, распол с конкретным человеком выше
порога), либо, если фактов пока мало, общий порог по тени — и только как
крайний случай, никогда не наоборот.

## Механика

**`S.мир.слухиОГерое`** — новый массив id (аналог `S.мир.флаги`, только про
героя, не про место). Проверяется раз в день, в `закончитьДень`, — той же
точкой, что и `проверитьСроки` дел, если они уже есть, но независимо от них:

```js
export function обновитьСлухи(S, итог) {
  for (const [id, з] of Object.entries(СЛУХИ)) {
    if (S.мир.слухиОГерое.includes(id)) continue;
    if (з.условие(S)) {
      S.мир.слухиОГерое.push(id);
      итог.причины.push(`По городу уже говорят: ${з.коротко}`);
    }
  }
}
```

Порядок в реестре важен: `Object.entries` идёт по порядку объявления, а
проверка «continue, если уже есть» означает, что первая подошедшая запись
и остаётся единственной **для одного и того же повода** — реестр ниже
специально пишет сначала конкретные факты, потом общие пороги, чтобы при
прочих равных выигрывал факт (см. правило выше).

## Реестр — `данные/слухи-о-герое.js`

```js
export const СЛУХИ = {
  // конкретные факты — сначала
  vozit_dlya_nozhey: {
    коротко: 'носит грузы Ножам, не спрашивая, что внутри',
    условие: S => S.мир.дела?.yashik_ne_po_opisi?.статус === 'готово',
  },
  pishet_dlya_kartelya: {
    коротко: 'носит бумаги картелю',
    условие: S => S.мир.дела?.vest_s_barzhi?.статус === 'готово',
  },
  svoy_u_sibilly: {
    коротко: 'свой у аптеки Сибиллы Рейн',
    условие: S => (S.мир.люди.sibilla?.распол ?? 0) >= 3,
  },
  svoy_u_doma: {
    коротко: 'свой у дома Ярны — и не по той причине, о которой сперва думаешь',
    условие: S => (S.мир.люди.yarna?.распол ?? 0) >= 3,
  },
  prosit_ne_za_sebya: {
    коротко: 'умеет просить не только за себя',
    условие: S => S.мир.дела?.slovo_pered_yarnoy?.статус === 'готово',
  },
  lyubopytnyy: {
    коротко: 'слишком много спрашивает про то, что его не касается',
    условие: S => ['pravda_o_kladbishche', 'odin_dorr_ili_dva']
      .filter(id => S.мир.дела?.[id]?.статус === 'готово').length >= 2,
  },
  // общий резерв — только если ни один факт выше ещё не сработал
  za_nim_hodyat: {
    коротко: 'за ним последнее время кто-то ходит',
    условие: S => (S.мир.тень ?? 0) >= 2,
  },
  o_nyom_sprashivayut: {
    коротко: 'о нём расспрашивали в доках',
    условие: S => (S.мир.тень ?? 0) >= 1,
  },
};
```

(Первые шесть зависят от «Дел» — если та механика ещё не собрана, они просто
никогда не сработают, реестр от этого не ломается, `S.мир.дела?.` — с
защитой. Последние два не зависят ни от чего нового: `S.мир.тень` уже растёт
в игре сейчас, задание можно выполнять и без «Дел».)

## Где это видно игроку

**Строка в журнал дня** — в момент, когда слух впервые сработал (уже в коде
выше, `итог.причины.push`).

**Вступление нового человека.** `движок/разговор.js`, `видСцены()`, строка
566:

```js
реплика = с.реплика || (с.нужнаСцена ? '' : ч.вступление ?? '');
```

Меняется на:

```js
const впервые = !S.мир.люди[кто];
const слух = впервые && последнийСлух(S);
реплика = с.реплика || (с.нужнаСцена ? '' : (слух?.вступление ?? ч.вступление ?? ''));
```

где `последнийСлух(S)` — новая функция в `движок/дела-слухи.js` (или прямо в
файле реестра): берёт последний по порядку добавления id из
`S.мир.слухиОГерое` и, если у него в реестре есть отдельное поле
`вступление` (не у всех — только у тех, для кого имеет смысл, чтобы **новый**
человек заговорил об этом первым делом; см. ниже), возвращает его.
**Важно:** проверка `впервые` должна идти строго до любого места, которое
создаёт запись `S.мир.люди[кто]` — то есть до вызова `человек(S, кто)` для
этого id в текущем кадре; `видСцены()` сейчас его не создаёт (только читает),
так что порядок уже правильный, трогать не нужно.

Не у каждой записи реестра есть смысл становиться вступлением — «за ним
кто-то ходит» и «носит грузы Ножам» это тревожная, разговорная вещь, которую
незнакомец не скажет в лицо при знакомстве; а вот «свой у Сибиллы»/«умеет
просить не за себя» — ровно то, чем открывают разговор с человеком, который
уже наслышан. Добавить в реестр только двум-трём записям своё `вступление`:

```js
svoy_u_sibilly: {
  ...,
  вступление: 'О тебе кое-что слышал — что к Сибилле ты вхож. Это уже кое-что значит.',
},
prosit_ne_za_sebya: {
  ...,
  вступление: 'А, это про тебя говорили — что умеешь просить не только за себя. Посмотрим.',
},
```

Остальные — только строка в журнал и, если у автора будет желание, годятся
для будущей темы «Сидеть и слушать» (не делаю этого сейчас: пул тем места —
чужая ответственность каждого файла `данные/места/*.js`, мешать в него слухи
о герое отдельным заходом рискованно, лучше отдельной, явной правкой позже).

## Почему это работает уже сейчас, при четырёх местах

Кажется, что смысл появляется только с новыми точками этапа 9 — но нет:
«Синий час» — семь человек, и первая встреча с каждым из них (кроме того,
с кем герой заговорил в первый вечер) уже происходит **позже**, на другом
визите, когда какой-то факт вполне мог успеть случиться. Проверка на бумаге:
начал с Ярны в первый вечер, к четвёртому визиту распол с Сибиллой дошёл до
3 — и первая встреча со старшей или с Олой (кто бы ни оказалась не встречена
раньше) уже вправе получить вступление `svoy_u_sibilly`. Ничего не нужно
ждать.

## Решено

| Вопрос | Решение |
|---|---|
| Новая шкала? | Нет — массив id, как флаги, не число |
| Слух может пропасть? | Нет в этой версии — раз сказано, город не забывает (тень пока тоже только растёт в коде, симметрично) |
| Слух влияет на цены/доступ? | Нет, только на текст — не тот случай, что «нельзя стат без трёх эффектов»: это не стат вообще |
| Что, если сработали два факта разом? | Побеждает добавленный раньше (порядок `S.мир.слухиОГерое`, `последнийСлух` берёт последний **добавленный**, не «самый сильный» — проще и достаточно) |

## Задание

1. **`данные/слухи-о-герое.js`** — реестр `СЛУХИ`, ровно как выше.
2. **`движок/состояние.js`** — `новоеСостояние()`: `S.мир.слухиОГерое: []`.
   Версия состояния растёт на единицу (или на ту же, что уже поднята заданием
   «Дела», если оба задания выполняются в одну сессию, — не заводить два
   отдельных шага миграции, если оба уже в работе, объединить).
3. **`движок/время.js`, `закончитьДень`** — вызвать `обновитьСлухи(S, итог)`
   рядом с `проверитьСроки` (если «Дела» уже есть) или отдельной строкой,
   если ещё нет — порядок между ними не важен, они не читают друг друга.
4. **`движок/разговор.js`, `видСцены()`** — правка вступления, как описано
   выше; импортировать `последнийСлух` из файла реестра.
5. **Тест.** Новый файл `тест/слухи.mjs`: (а) на пустом состоянии
   `обновитьСлухи` ничего не добавляет; (б) при `S.мир.тень = 2` после
   вызова появляется `za_nim_hodyat`, не `o_nyom_sprashivayut` (порядок
   реестра — только одна запись на факт, но обе условия здесь одновременно
   истинны при тени 2: возможная неоднозначность — **явно решить**: если оба
   условия по тени истинны разом, добавлять **обе** записи (тень 2 не
   отменяет тень 1, это разные высказывания о разной степени) — тест это
   и проверяет, не «одна из двух»; (в) `видСцены()` не подставляет
   вступление для человека, с которым уже была хоть одна сцена
   (`S.мир.люди[id]` существует).
6. **Браузер:** новая игра → любым способом поднять распол с Сибиллой до 3
   (или, если «Дела» уже собраны, завершить `yashik_ne_po_opisi`) → зайти
   туда, где герой ещё не был, к человеку, с которым сцены ещё не было, →
   вступление другое.

Коммит, push. Отдельного «Порт-тексты» не требуется — реплик всего две-три,
они уже дописаны в реестре целиком.
