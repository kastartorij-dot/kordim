# Промпт: исправление первой пачки диалогов и правила для следующих

Переработай свои файлы `00_ФОРМАТ_и_общее.md`, `01_Старшая.md`, `02_Ола.md`, `03_Ния.md` с учётом замечаний ниже. Затем применяй эти правила к следующим персонажам. Сейчас задача — подготовить хорошие тексты и однозначное описание их работы для внедрения.

Проверены именно эти четыре файла. В общем документе перечислены также Фрея и Повариха, но их отдельные файлы в проверенную пачку не входили: считать их проверенными нельзя. Обещания их будущих реакций ниже — зависимости, которые ещё нужно закрыть.

## Оценка пачки и что сохранить

Это содержательный литературный черновик, который требует правки перед внедрением. Напрямую подключить эти Markdown-файлы к игре нельзя; готового преобразователя представленного формата нет. Заявление «один к одному переводится в JS» сейчас неверно: есть несовместимые поля, неоговорённые переходы и незавершённые последствия.

Сохрани удачные решения:

- Конкретные варианты героя вместо общего переключателя «мягко / прямо / деньгами».
- Бытовые действия: бельё Олы, стакан старшей, музыка снизу, разговор о доле Нии.
- Возможность посидеть, помочь, отказаться и не рассказывать о себе.
- Самостоятельность Нии и факт выплаченного долга.
- Осторожность с противоречивой историей сына: до решения автора не закреплять, чей он и когда умер.
- Различие между платой за услугу и доверием к человеку.

Типы остаются такими: старшая и Ола — значимые, Ния — ключевая. Фрея и Повариха — значимые. Сиб остаётся образцом подробной реализации. Для значимого НПС ориентир — 3–5 основных тем, короткие уточнения и 1–2 содержательных последствия; число не жёсткая квота, но сложность должна оставаться небольшой.

## 1. Сначала исправь технический договор

Проверка проведена по действующему коду в папке `Порт`, прежде всего `движок/диалог.js`, `движок/разговор.js`, `движок/голоса.js`, `движок/сроки.js`, `движок/знание.js`, `данные/диалоги/сиб.js`. Концепт может описывать желаемое устройство; реализованные возможности проверяются по коду.

### 1.1. Приведи описание к реальным полям

| Сейчас в пачке | Как устроен действующий граф |
|---|---|
| Вариант `{я, э, дальше}` | Вариант `{ид, текст, эффект, дальше}`. `ид` обязателен для устойчивых переходов, проверок и защиты наград от повторов. |
| Эффект рядом с текстом узла | `узел.при`; можно передать массив отдельных эффектов. Для выбора используется `вариант.эффект`. |
| `ужеГоворили` | `ветка.уже`: массив строк. Список повторных ответов нужно привязать к конкретной ветке. |
| `доверие: +1` как эффект | `{распол: {ola: 1}}`, с id нужного человека. Ключ `доверие` в эффектах не начисляет расположение. |
| `сыт: {до: 1}` и подобные условия | Диапазон `[минимум, максимум]`, например `сыт: [0, 1]`. Объект вместо массива вызывает ошибку. То же для `цел`, `тепло`, `хмель`, `напряжение`, `вид`. |
| `доверие: {кто, от}` | В графе `доверие: 2` проверяет текущего собеседника. Объект с другим человеком здесь не поддерживается. |
| `голос: {имя, от}` / `голос отец ≥ 1` | Условие `голос: 'ОТЕЦ'` проверяет, слышен ли голос. Имена регистрозависимы: `ИГЛА`, `МОЛВА`, `ЖАР`, `ОТЕЦ`. |
| `ремесло наколки ≥ 1` | Условие `ремесло: 'наколки'` проверяет наличие ремесла. Проверки числового уровня в этой форме нет. Голос ИГЛА связан со стартовым ремеслом; изучение наколок позднее не открывает его автоматически. |
| `голос: {игла: +1}` как эффект | Такой эффект не поддерживается. Есть `открыть` и `зарубка`; успешная активная проверка уже обрабатывает развитие голоса. Не добавлять вторую произвольную награду. |
| `→ конец` | Нужно явно различить `дальше: 'хаб'` и `дальше: 'закрыть'`. Возврат к темам и завершение разговора — разные действия. |
| Стрелка после текста узла без выбора | Автоматический переход из обычного узла не реализован. Нужен вариант «Продолжить» / «Понятно» либо текст нужно включить в ответ предыдущего выбора. |

Для проверок укажи `проверка: {голос: 'ИГЛА', порог: 'лёгко', тип: 'белая'}`, а также отдельные результаты `успех` и `провал`. Это пример формы; сам текст проверки у Нии требует правки ниже.

ЖАР в действующей системе становится слышен при напряжении от 2. Условия «напряжение от 1» в пачке сами по себе не заставят его прозвучать на единице: учитывается ещё слышимость голоса.

Markdown может остаться авторским форматом. Но значения и переходы должны иметь однозначный перевод. Новые возможности помечай отдельным списком задач внедрения, а не описывай как уже существующие.

### 1.2. Не возвращай систему манер под новыми названиями

В карточках введены массивы `отзывается / не_терпит`, включая новую «жалость». Текущий движок их не читает: он сравнивает `манера` с одиночными `любит / обижает`. Кроме того, реакция на вариант учитывается по варианту, а не автоматически один раз на всю ветку, как написано в общем файле.

Для этой пачки убери автоматические награды за ярлыки манер. Пиши конкретные варианты и явно задавай итоговое изменение расположения там, где оно оправдано. Авторская заметка «сказано осторожно» допустима, но не должна подразумевать скрытый дополнительный +1. Тогда разговор не превращается в подбор понравившегося НПС тега.

Не называй простой вопрос «Что за дом? Хочешь рассказать?» автоматически жалостью, а «Откуда она взялась?» — автоматически нападением. Реакция должна следовать из слов и ситуации.

### 1.3. Не используй повторяющиеся ключи

У старшей в `порядок / цены` записано `{тема: muzykant, тема: ceny}`. В `цветок / закрыто_жёстко` два ключа `флаг`. При переносе в объект JS останется только последнее значение.

Задавай несколько эффектов отдельными записями. Для входа в узел существует `при: [{тема: 'muzykant'}, {тема: 'ceny'}]`. Не заменяй это на массив в `тема` или `флаг`: такие массивы не объявлены поддерживаемым форматом текущего обработчика.

### 1.4. Раздели память по назначению и сроку

- `факт` в графе хранится у конкретного НПС. Другой человек его автоматически не видит.
- `флаг` в обработчике места хранится у места либо в текущем визите. Флаг места не становится автоматически глобальным флагом мира.
- Временные флаги нужно перечислить в `флагиВечера`. Сейчас они сбрасываются на входе в новый визит, а не отдельным автоматическим действием «утром».
- Для каждого нового состояния укажи: кто ставит, кто читает, где хранится, когда снимается, что происходит при повторе и загрузке сохранения.

Конкретный разрыв: в общей таблице `знает_про_зиму` назван флагом, а Ола ставит `факт`. Фрея при таком переносе не получит обещанного условия. Такие расхождения устранить во всей таблице.

`музыкант_своё` относится к текущему посещению, если означает «сегодня уже играл». `помог_оле` — долговременное воспоминание. Их нельзя хранить с одинаковым сроком по умолчанию.

### 1.5. Не превращай слух в доказанный факт

У старшей в `долги / слышу` стоит `{слух: dolgi_doma, тема: dolgi_doma}`. Действующий обработчик сначала выдаёт слух, затем обычная `тема` повышает его до «подтверждено». Это прямо противоречит назначению ветки «получить слух, не свидетельство».

Для такого результата оставь только выдачу слуха: она уже делает тему известной. Не повышай достоверность без основания. `pigment_кухня` из Нии отсутствует в реестре тем: либо оформить новую тему и её свойства при внедрении, либо оставить подсказку текстом/локальной памятью. Не создавать неописанные записи знаний.

### 1.6. «Видят» сейчас показывает текст

Эффекты `сыт +1, раз` в трёх блоках «Видят» не выполняются. Это текстовая реакция без применения `э`; ключ «раз» также не задаёт защиту от повторения.

Лучшее простое решение: НПС предлагает хлеб, игрок выбирает взять/съесть, и отдельное действие применяет один эффект. Если оставляешь автоматическое кормление, явно опиши нужный обработчик и предел «один раз за визит» либо «один раз за день». Не лечить голод бесконечным открытием беседы. У старшей герой не должен становиться сытым только от совета сходить за хлебом на кухню.

### 1.7. Опиши все завершения, приветствия и способы уйти

В режиме узла интерфейс показывает его варианты; отдельная общая кнопка выхода там не добавляется. Многие узлы в пачке имеют только продолжение беседы. Добавь понятный выход там, где игроку предлагают продолжать личный разговор, и явное завершение у каждого конечного узла.

У Нии ветка `выход` сама по себе не включится при «Отойти»: этот путь в текущем коде закрывает диалог напрямую. Автоматическое прощание сейчас подключено к выходу через дверь места. Нужно отдельно описать вызов прощания Нии при уходе от неё.

Условные приветствия со своими эффектами тоже не появляются из списка Markdown автоматически. Поле `снова` само по себе не реализует таблицу условий и штрафов. Либо выразить приветствие существующими узлами, либо указать конкретную небольшую доработку подключения.

Переход «ветка `порядок`» оплачивает новую ветку и использует механизм возврата к источнику. У старшей после перехода из `монета` укажи, куда возвращается игрок: обратно к оплатившему узлу, в список тем или из разговора. Простое `хаб` из вложенной ветки не всегда означает глобальный список тем.

### 1.8. Не потеряй существующие действия при переходе на граф

Подключение через `ДИАЛОГИ[нипс]` переключает интерфейс на действия графа. Поэтому отдельно проверить:

- Существующие две сцены близости Нии: где останется действие «Остаться» и как его вызвать. Наличие файлов сцен само по себе не сохраняет кнопку.
- Доступ к Ярне: сейчас уже есть проход по отношению дома и платный вариант за 40 грошей. Новая плата 20 грошей старшей «чтобы сегодня» требует определённого результата; будущая реплика Ярны без реализованного доступа недостаточна.
- Музыканта: существует действие оплаты 20 грошей с флагом `музыка`, временем и реакциями дома/работниц. Новые способы оплаты должны согласованно обновлять это состояние; нельзя получить разные версии одного вечера в трёх разговорах.

В графе `стоит` у варианта проверяет доступность и показывает цену, а списание задаётся эффектом. У обычного действия комнаты цена может списываться обработчиком самого действия. При переносе определить одно место списания, исключить двойную оплату и отрицательный кошелёк.

## 2. Прогрессия, доверие и обещания

### 2.1. Проверь первое знакомство и восстановление разговора

Не делай все пути знакомства одноразовыми, если остальные ветки закрыты доверием. У Нии после варианта с монетой и быстрого завершения может остаться отрицательное расположение; остальные темы требуют от 0 или от 1. У Олы после простого «Отойти» останется 0, а остальные темы требуют от 1. При буквальном ограничении «только первая встреча» дальнейший разговор окажется закрыт.

Оставь нейтральную повторную тему, доступную при низком доверии, либо конкретный способ исправить первое впечатление. Это не должно позволять бесконечно получать расположение за повтор одних слов.

В текущем коде ограничение первых веток использует число визитов в место. Это отличается от первой встречи с конкретным человеком. Поле `первая: true` разрешает ветку на первом визите, но само по себе не запрещает её на последующих. Оговори, какой именно смысл нужен каждой ветке; не путай знакомство, открытие окна разговора и новый вечер в доме.

### 2.2. Снизь количество наград за обычные ответы

Текущее расположение ограничено диапазоном от −2 до 4. У Олы путь «помочь с бельём» (+2) → «тебя не обижают?» (+1) даёт почти максимум за одну ветку; предполагаемая автоматическая манера может довести его до максимума. Большинство дальнейших порогов после этого ничего не разделяет.

У Нии почти любое уважительное продолжение даёт +1/+2. Общение превращается в быстрый набор правильных ответов. Обычным вопросам часто достаточно содержательного ответа без изменения отношений. Награждай конкретный поступок или действительно важное решение; личные открытия можно связать с пережитым событием и памятью о нём.

Не меняй числовую шкалу движка ради этой пачки. Пересчитай пути на существующей шкале и укажи итог после нескольких характерных маршрутов.

### 2.3. Уложи ветки во время визита

У дома 6 ходов, подъём в комнату Нии стоит 2. Ветка на 2 хода при уже потраченных 3 доступна, при потраченных 4 — недоступна: движок оставляет запас до завершения вечера. Следовательно, `поздно` с `ходыОт 3` имеет узкое окно. Ветка достижима, но это нужно учитывать, а не обещать её после любого набора разговоров.

Покажи по одному рабочему маршруту открытия каждой важной темы с учётом стоимости комнаты, текущего доверия и повторных визитов. Отдельно проверь `остаться` и `поздно`.

Бесплатная `музыка` у Нии включает уход вниз, оплату и возвращение, хотя существующая оплата музыканта стоит ход. Согласуй стоимость одинакового события во всех местах доступа.

### 2.4. Не выдавай обязательство, которое нельзя выполнить

- Ния: встреча через три дня у ворот пока не написана. Сейчас игрок получит обязательство без действия выполнения и рискует получить штраф за отсутствие реализации. До готовности встречи оставь её идеей следующей пачки без активного таймера и наказания либо опиши весь путь выполнения в этой пачке.
- Ния: разговор через 30 дней выходит за заявленную в ГДД длительность первого сезона — 30 дней. Любое принятие в ходе сезона назначает встречу уже за его пределами. Перенеси крючок в доступный срок или явно отложи на будущий сезон без действующего обязательства.
- `обещание: {дней: 3}` сейчас задаёт крайний срок до конца вечера третьего дня. Это не точное назначение встречи «через три дня днём». Нужно различить срок выполнения и окно встречи.
- Ола: «не рассказывать» — длительное условие поведения, а не задача, автоматически проваленная по истечении 30 дней. Опиши нарушение, успешное сохранение тайны и момент завершения, либо используй простую память об обещании без срока.

Для каждой обещанной встречи/тайны перечисли: принятие → доступное действие выполнения/нарушения → изменение статуса → одна реакция. У повторного приветствия по истёкшему обещанию штраф должен сработать один раз, а не при каждом разговоре.

### 2.5. Закрой расхождения между таблицами и узлами

- У Олы реакция на нарушение обещания описана только в конце файла. В таблице возвращения её нет; не определены событие нарушения и состояние, которое читается.
- Там же бонус от `помог_оле` в ветке `ласточка` заявлен после всего диалога, но в самой ветке не описан.
- У Нии память `видел_промах_ния` обещает реакцию при возвращении, которой нет в таблице возвращения.
- У Нии `проверка` возвращает к вариантам «1–2–4», но скрытие варианта 3 только написано в скобках. Нужен отдельный узел или явное условие. Действующий движок защищает расположение за один вариант от повторного начисления, поэтому не объявляй это автоматически бесконечным фармом; всё равно нужен правильный маршрут.
- Выдача флагов будущей Ярне/Фрее должна иметь читателя в согласованном файле. Пока читателя нет, не считать последствие готовым.

## 3. Лор и характеры

### 3.1. Не превращай пробел справки в новый установленный факт

«В источниках не описано знакомство с Бренном» не равно «этот человек Бренна не знает». «Личная цель Нии пока не написана» не равно «Ния сама не придумала, чего хочет». Утверждения, что работницы не знают ничего за пределами дома, тоже слишком сильны: они живут в городе.

Обычные бытовые подробности можно предлагать свободно. Новые устойчивые черты, прошлое, большие связи и обещанные сюжетные события вынеси в короткий список новых предложений. Не представляй их как уже известный лор. Например: абсолютное «старшая никогда не извиняется», новое расписание Нии и её отдельная встреча у ворот.

В `00` ошибочно сказано, что Сванны нет в реестре. Она есть в резерве «Синего часа», но не подключена к текущим комнатам. Убрать её упоминание для простоты допустимо; обосновывать это отсутствием персонажа нельзя.

Удаление упоминаний сына из этой пачки не исправляет автоматически старые реплики Ярны, Фреи и Поварихи в игре. Отметь эту общую зависимость: при частичном внедрении новые уклончивые ответы будут соседствовать со старыми прямыми утверждениями. До авторского решения не объявляй противоречие устранённым во всём доме.

### 3.2. Ния: сохранить хронологию и самостоятельность

В действующем тексте её долг составлял 90 кордов и выплачивался четыре года. В новой ветке `остаться / ответ` фраза «Первый год — потому что была должна. Потом — потому что боялась…» создаёт впечатление, что долг закончился после первого года. Перепиши так, чтобы четыре года долга и последующее решение остаться были ясно различимы.

У неё есть право уйти и право отказать гостю. «С Ярной я не спорю никогда» вводит абсолютное подчинение, которого для этого образа не требовалось. Уточни конкретные правила дома и область решений хозяйки.

В `границы / вежлив` ответ «Но попробуй. Я люблю наблюдать» вместе с одобрительной репликой ЖАРА превращает разговор о твёрдом отказе в приглашение его преодолевать. Если это шутка, её смысл должен сохранять силу «нет». Также различи отказ от конкретного действия и немедленное изгнание гостя: сейчас фраза «сказала я — ты выходишь» смешивает эти вещи.

Отказ от дневной встречи заявлен нормальным исходом. При возвращении «Это не обида: это счёт» звучит как скрытый упрёк. Согласуй реакцию с заявленным смыслом отказа.

Сохрани узнаваемую комнату: в текущей игре она узкая и высокая, с зеркалом в полный рост как единственной дорогой вещью. Новая версия теряет зеркало и переносит внимание на окно во двор, сближая сцену с комнатой Фреи. Новая деталь допустима, но не стоит стирать уже отличающийся образ комнаты.

### 3.3. Старшая: выправить обращения и предметы

- В `цветок / старт` герой спрашивает у самой старшей: «Что у старшей случилось?» Это остаток общего вопроса из старой системы. Нужна реплика, обращённая к ней лично.
- «Как его звали?» предполагает, что герой уже знает о конкретном умершем мужчине. Если такого знания ещё нет, условие или формулировка должны это учитывать.
- В возвращении после ухода старшей из кухни звучит «Хозяйка вышла». Хозяйка дома — Ярна. Назови именно старшую.
- В карточке она боится тишины; почти весь диалог затем хвалит молчание. Эти чувства могут сосуществовать, но нужна ясная причина различия; сейчас выглядит как невыдержанная черта.
- Цветок еженедельно меняется, а теперь это горшок с растением и новыми листьями. Определи, что именно меняют: срезанный цветок или горшечное растение. Не описывай недельное увядание и замену так, будто это одно и то же без объяснения.
- «Вот. Её жалеют все, а ты даже не пробуешь» в ответ на «Привычка — это не так мало» не имеет ясного адресата: кого «её»? Перепиши.
- `цветок_закрыта_на_вечер` должен закрывать тему либо всю беседу — выбери одно. Сейчас условия ветки обещают запрет темы, а приветствие «Не сегодня» может быть прочитано как запрет всего разговора.

### 3.4. Ола: оставить живость, добавить взрослую компетентность

Помощь с бельём и радость от оплаченного долга работают. Но почти каждый узел содержит «ой», панику, сияние, благодарность или нужду в одобрении героя. Из-за этого работница превращается в беспомощную девочку.

Оставь часть заминок, но дай ей уверенно знать работу, самой решать, когда закончить разговор, поправить гостя по делу или отказать без извинений. Нужна хотя бы небольшая перемена настроений. «В голове только до ста» — новая характеристика ограниченности; для её роли она не нужна и не следует из лора.

Фраза героя «Дурацкая. Но твоя» не должна автоматически получать благодарность и +1 лишь потому, что Ола любит ласточку. Возможна смешанная реакция, но она должна быть психологически подготовлена. Так же вопрос «Ты счастлива тут? По-настоящему?» слишком быстро требует исповеди от недавно встреченного человека; перенеси глубже или приземли к конкретному дню.

У Олы `ола_убежала_на_вечер` не делает её недоступной в описанном возвращении — она тут же здоровается. Реши: она ушла до следующего визита или только отказалась от темы. Название состояния и поведение должны совпадать.

Узнавание наколочника можно сделать отдельным условным вариантом по началу героя. Нейтральная версия без имени мастера безопаснее для всех начал, но не утверждай, что прежнего знакомства точно не было.

### 3.5. Новые сведения о доме

Две фигуры у чёрного хода, голый торс/отсутствие куртки круглый год, правило одного кувшина на человека, точное число отказов Нии за год — новые сведения. Они не обязаны быть плохими, но должны быть помечены предложениями. Для слуха о выплатах достаточно наблюдаемой детали; не нужно придумывать целую новую систему визитов сборщиков ради одной ветки.

В `музыка / старт` Ния говорит «Сегодня не просили» даже когда флаг уже сыгранного «своего» установлен. Вступление должно зависеть от состояния. «Никто другой не платит двадцать» также сильнее, чем её доступное знание; лучше оставить наблюдение про этот вечер.

## 4. Литературная правка

### 4.1. Слишком много общих афоризмов

Старшая и Ния часто звучат одним авторским голосом: «это не X, это Y», «это дешевле», «ты умеешь слушать», «редкий ответ», «это честно», похвала за молчание. Ола тоже начинает говорить теми же формулами: «ничего не значит — значит всё».

Примеры, которые стоит упростить или заменить конкретным действием:

- «Объяснения — это уже вино».
- «Справедливая. Это хуже».
- «Благодарность — это долг, который не вписан».
- «Ты говоришь, чтобы это стало слышно. Вот, слышно».
- «Это не приглашение, это ноги».

Несколько выразительных фраз оставить можно. Пусть между ними будет обычная речь: про работу, просьбу, случай, человека. Не заканчивай каждый маленький обмен итогом о жизни.

У старшей больше хозяйственной конкретики и редкая сухая шутка. У Олы больше живой бытовой истории и увлечённости своим делом. У Нии прямота, собственное мнение и способность заинтересоваться собеседником без постоянной оценки его «правильности».

### 4.2. Не копируй голос Сиба

Ния в `поздно` почти повторяет его узнаваемую реплику: «Тихо. Это плохо. В тишине люди начинают говорить». Перепиши именно её повод перейти к личному. Используем Сиба как образец устройства веток, а не как источник одинаковых интонаций всем людям дома.

### 4.3. Проверка наколки должна быть связной

Герой вслух говорит о подновлении татуировки. При провале внутренний голос думает «клеймо», и Ния отвечает «Это не клеймо», будто услышала внутреннюю мысль. Исправь причинность: либо герой действительно произносит ошибочное предположение, либо Ния отвечает на реально сказанные слова. НПС не слышат внутренние голоса.

Период «не реже раза в два года» нельзя уверенно считывать с наколки как календарную отметку. Можно заметить старую линию и более свежую работу; точный интервал расскажет сама Ния. Факты наколки одинаковы при успехе и провале: меняются точность наблюдения, формулировка героя и реакция.

После провала заявлена белая проверка с возможностью повторения при изменившихся обстоятельствах. Но если ветка завершается как «пройдена» и далее выдаёт только `уже`, до проверки больше не добраться. Укажи результат завершения так, чтобы белая проверка и повтор ветки не противоречили друг другу.

«Хочешь трогать — не здесь. Здесь я не про кожу» в комнате Нии выглядит как неудачно перенесённый старый ответ о работе наколочника. Уточни, о чём именно она говорит: осмотр, подновление или прикосновение. Сохранение старой фразы не оправдывает бессвязность новой сцены.

### 4.4. Приведи действия и обещания текста к результату

Не описывай исчезновение НПС, наступление ночи, поход в другую комнату или изменение музыки, если состояние сцены остаётся прежним. Допустим текстовый монтаж, но он должен иметь согласованную стоимость и итог. Свеча, придвинутая к замёрзшему человеку, не заменяет реального источника тепла; для проявления заботы проще предложить место, ткань или тёплое питьё.

Заявленная подготовка «под будущую героиню» сейчас всё равно непоследовательна: в репликах есть «ты уже отдал», «ты спрашивал», «смелее, чем был бы трезвым». В текущей игре герой — Одвин. Не усложняй первую пачку незаказанной системой рода. Если нейтральная редакция всё же нужна как отдельная задача, применять её следует последовательно.

## 5. Формат следующей версии

Верни исправленные четыре файла, а в общем файле добавь:

1. Краткий перечень исправлений, сгруппированный по совместимости, маршрутам и литературной правке.
2. Таблицу новых состояний: id, факт/флаг/обязательство/тема, владелец, срок жизни, место установки и все места чтения. Для обещания — способ выполнить или нарушить.
3. Отдельный список предложенного нового лора и зависимостей от ещё не написанных сцен.
4. Для каждой ветки: условие доступа, точная реплика входа, цена ходов, варианты с устойчивыми id, итог, повторное поведение. Название темы в шапке само по себе не выдаёт знание: место выдачи должно быть явным.
5. Проверку характерных маршрутов из таблицы ниже. Если у тебя нет доступа к игре, назови это проверкой схемы на бумаге и не заявляй, что файлы запускались.

| Сценарий | Что проверить |
|---|---|
| Первое знакомство, сразу отойти | Можно ли снова начать нормальный разговор; не закрылась ли единственная доступная ветка. |
| Ния, деньги первым, затем завершить | Есть ли честный путь восстановления после низкого доверия. |
| Мало денег и ровно нужная сумма | Нет отрицательного кошелька, двойного списания и скрытой платы. |
| Голодный герой открывает разговор повторно | Еда получена только предусмотренным действием и не выдаётся бесконечно. |
| Повтор ветки в том же и следующем визите | Верное приветствие, завершение, стоимость; прежняя награда не повторяется. |
| Слух о долгах дома | Остаётся слухом, пока не появилось основание подтвердить. |
| Музыкант оплачен в зале, затем разговор с Нией | Общая память согласована; Ния не говорит, что никто сегодня не платил. |
| Ола рассказала про зиму | Фрея получает нужное условие; обещание имеет определённые выполнение/нарушение. |
| Старшая прервала разговор | Тема/НПС закрыты ровно на заявленный срок; прочие выходы доступны. |
| ИГЛА недоступна / успех / провал | Всегда есть путь дальше; голоса не слышны НПС; белую проверку можно повторить по её правилам. |
| Ния, 3 и 4 потраченных хода из 6 | Проверить доступность дорогих веток и путь через стоимость комнаты. |
| Уход от Нии и действие близости | Прощание вызывается правильно, старые сцены остаются достижимыми. |
| Обещание принято, выполнено, истекло | Никаких невыполнимых задач, штраф не повторяется, приглашение не сдвигается каждый раз на новые три дня. |
| Перезагрузка сохранения посреди ветки | Варианты, платежи, память и одноразовые эффекты сохраняют правильное состояние. |

Для следующих НПС сначала строй небольшую законченную беседу, затем добавляй только нужные последствия. Значимый персонаж может быть живым без большой системы манер, десятков перекрёстных флагов и таймеров. У ключевого НПС сложность допустима, когда каждый её элемент приводит к написанной и доступной сцене.
