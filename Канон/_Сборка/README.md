# Сборка канона из блоков

15.09.2026 мастер разрезан на отдельные файлы — по одной записи, герою, правилу,
приложению. `00_КАНОН_Мастер_Кордим.md` теперь **не редактируется руками** —
он собирается из блоков. Компакт (`01_Компакт_канон.md`) пока отдельный
документ и в сборку не входит — он организован по темам, а не по номерам
записей, и решать, как их состыковать, будем позже вместе с автором.

## Где что лежит

```
Канон/
  00_шапка.md          обложка + журнал правок (единственный «блок», где
                        разрешено писать о снятых вещах — это история решений)
  Герои/                Грейс, Никто, Связь с Грейс
  Правила/              7 файлов — правила ведения (роли, физика боя, стиль…)
  Записи/               56 файлов, 00–55, лорбук
  Приложения/           хронология, имена из арок, что заряжено, опорные цифры…
  манифест.json         порядок блоков для сборки — генерируется, не редактировать руками
  запреты.txt           список снятых формулировок для проверки
  _Сборка/               эти три скрипта
```

Каждый блок — YAML-шапка (`id`/`title`/`часть`/`раздел`/`статус`/`ключи`) и
тело — дословный кусок исходного мастера. Шапка — метаданные для будущей
вкладки «Канон» в вики (чипы, фильтры, статус), тело не трогается сборкой.

## Скрипты

- **`split.mjs`** — режет мастер на блоки. Запускать только если понадобилось
  перенарезать с нуля (структура частей/записей мастера почти никогда не
  меняется — обычно достаточно просто редактировать нужный блок вручную).
- **`build.mjs`** — собирает мастер обратно из блоков.
  - `node Канон/_Сборка/build.mjs --check` — только сверяет, ничего не пишет.
    Гоняется после любой правки блока, чтобы убедиться, что порядок и текст
    не разъехались.
  - `node Канон/_Сборка/build.mjs` — пересобирает и перезаписывает
    `00_КАНОН_Мастер_Кордим.md`. Запускать после каждой правки блока, которую
    утвердил автор.
- **`validate.mjs`** — ищет в блоках снятые формулировки из `запреты.txt`
  (Гильдия наёмников, гримдарк, латинские Nemo/Nobody и т.д.) и записи без
  ключей. С 17.09 заодно смотрит `Проза/` и данные сайта `Игры/Сайт/Приложение/Данные`.
  С 08.11 — что каждая подстановка `{{…}}` в блоках существует, и что население городов
  в компакте совпадает с данными (компакт пишется руками и подстановок не знает).
  Ничего не чинит, только показывает, где смотреть.
- **`check-data.mjs`** — связность данных сайта: люди, места, фракции, тракты,
  сюжетные линии существуют; у каждого события есть уникальный `slug`; в «Заряжено»
  столько же пунктов, сколько в `Приложения/что-заряжено.md`. Проверяет положительные упорядоченные диапазоны `days` и способы передвижения в `winterClosed` трактов. Проверяет также привязки `Данные/sources.js`: у каждой карточки человека, места, фракции, статьи и события есть существующие блоки канона, без повторов и ссылок на удалённые карточки. С 06.11 — что у каждой картинки, упомянутой в данных (`Лица/…`, `Места/…`), есть файл в `Игры/Сайт/Изображения/`. Гоняется на GitHub.
- **`export-wiki.mjs`** — собирает вкладку «Канон» из блоков и ленту правок для главной (`Данные/journal.js`, датированные записи журнала из `00_шапка.md`). С 08.11 собирает и то, что раньше правилось руками: `Данные/sources.js` — из `links` в шапках блоков, `Данные/questions.js` — «Заряжено» из приложения «Что заряжено» (люди пунктов — в его шапке, поле `люди_пунктов`), «Открыто» из раздела плана «Ждёт решения автора»; `--check` сверяет сохранённый экспорт без записи, игнорируя дату сборки и различия переносов строк.
- **`export-scenes.mjs`** — собирает прозу для раздела «Арки»; необязательное поле `covers: slug, slug` в шапке связывает один рассказ с дополнительными событиями, проверяет их существование; `--check` сверяет её с исходниками без записи. Оба режима проверки запускаются в GitHub.
- **`export-plan.mjs`** — собирает `Канон/ПЛАН_развития.md` в `Данные/plan.js` для раздела «План» (отметки `[x]`, `[~]`, `[ ]`, `[3/13]`, `[-]`, трудоёмкость, **А**, дата `✓ ДД.ММ`); проценты считает страница. `--check` сверяет без записи, запускается в GitHub. Запускать после каждой правки плана.
- **`silence.mjs`** — «карта тишины»: кто вне хроники, где нет портрета, вида места,
  иллюстрации события, сцены, обложки статьи. Не проверка, а список, куда расти.

## Числа и связи (с 08.11)

**Числа живут в данных сайта, блоки на них ссылаются.** Цены и курс монет — `Данные/goods.js`
(`GOODS`, `COIN`), население — поле `pop` в `Данные/places.js`, скорость в пути и сроки трактов —
`Данные/routes.js` (`PACE`, `days`). В блоке вместо числа стоит подстановка, `build.mjs` и
`export-wiki.mjs` вставляют значение (`lib.mjs`):

| Подстановка | Что даёт |
|---|---|
| `{{price:horse-saddle}}` | «10–12 кордов» — монета и склонение выбираются сами |
| `{{price:horse-saddle\|число}}` | «10–12» |
| `{{price:job-special\|верх,число}}` | «300» — только верхняя граница |
| `{{coin:марка}}`, `{{coin:корд}}`, `{{coin:корд/марка}}` | «10», «200», «20» |
| `{{pop:brook}}` | «~2 000» — число из начала `pop` |
| `{{pace:foot}}` (foot, rain, horse, cart) | «20–25» — миль в день |
| `{{days:river.horse}}`, `{{days:river.foot\|число}}` | «2 дня», «4–5» |

Сейчас так написаны запись 15 (скорость, сроки трактов), 16 (вся экономика), 27 (города) и
приложение «Опорные цифры». Сменить цену — значит поправить `goods.js` и пересобрать мастер:
`build.mjs --check` и `export-wiki.mjs --check` упадут, пока этого не сделали. Опечатка в подстановке
роняет сборку. Кошелёк и калькулятор пути на сайте и статьи «Деньги» и «Дороги» берут те же числа.
Слова в прозе («семьдесят кордов — дом с коровой») — не подстановки: персонажи считают словами.

**Связи блока с карточками справочника — поле `links` в шапке.** Строка `вид:id`, вид — `people`,
`places`, `factions`, `articles`, `events` (у событий — `slug`). Пометка `главная` ставит этот блок
первым среди источников карточки. Из `links` собирается `Данные/sources.js` («Связанные записи
канона» на странице карточки) и чипы во вкладке «Канон». Новая карточка в справочнике — значит
строка в `links` нужного блока, иначе `check-data.mjs` скажет, что у неё нет источников.

## Порядок правки записи

1. Найти нужный файл в `Записи/`, `Герои/` или `Правила/`.
2. Показать автору карточку правки (было → стало), дождаться «да».
3. Отредактировать блок.
4. Добавить строку в журнал правок (`00_шапка.md`, раздел «Что изменено против исходника»).
5. `node Канон/_Сборка/build.mjs` — пересобрать мастер. До сборки расхождение `--check` после содержательной правки ожидаемо и само по себе не означает ошибку структуры.
6. `node Канон/_Сборка/build.mjs --check` и `node Канон/_Сборка/validate.mjs` — проверить результат сборки и снятые формулировки.
7. Догнать компакт вручную и карточки справочника; `node Канон/_Сборка/export-wiki.mjs` обновляет вкладку «Канон», `node Канон/_Сборка/check-data.mjs` проверяет связи. После изменения прозы отдельно запустить `export-scenes.mjs`.
8. `git add -A`, осмысленный commit и push (см. правило в `AGENTS.md`).

## Что не сделано

- Компакт не собирается из блоков — по-прежнему правится отдельно вручную.
- `раздел` у всех записей ЧАСТИ III сейчас общий — «Лорбук». Деление на
  тематические разделы (Фракции / География / Люди / Экономика…), как в
  макете `Игры/Сайт/Прототипы/canon.html`, ещё предстоит расставить и лучше — вместе
  с автором, а не угадывая.
