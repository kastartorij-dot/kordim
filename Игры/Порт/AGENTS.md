# ПОРТ — инструкции для работы

Рабочие исходники находятся здесь, в `Игры/Порт/`. Общие правила Кордима из корневого AGENTS.md остаются в силе. Старая папка `D:/AI/kordim/Порт` пустая и не является проектом.

- В начале сессии проверить Git и выполнить `git pull`; порядок синхронизации — `Документы/ПОРЯДОК_РАБОТЫ_И_ВЕРСИЯ.md`.
- Для поиска нужной системы использовать `КАРТА_ПРОЕКТА.md`. Для возобновления работы — `СОСТОЯНИЕ_ПРОЕКТА.md` и README соответствующего шага.
- Сначала искать нужные функции и разделы через `rg`, затем читать найденный участок и необходимые зависимости. Не читать весь ГДД, план, журнал или выгрузку диалогов при каждой небольшой задаче. Для сквозной задачи читать столько, сколько нужно для её проверки.
- Два плана и папки используют одни 17 шагов. Ш01–Ш17 в реестре — те же номера. Старые П/P01–22 разобраны в `Документы/Разработка/СООТВЕТСТВИЕ_СТАРЫХ_НОМЕРОВ.md`; исторические этапы ГДД и версии сохранений — отдельные номера.
- Документы конкретного шага лежат вместе в `Документы/Разработка/Шаг_XX_Название/`. Общие концепты хранятся один раз в `Документы/Общие_Материалы/`, из шагов на них ссылаются.
- `Документы/На_Разбор/` — входящая папка автора. После завершённого разбора сразу переносить файл по смыслу в папку шага, `Общие_Материалы/` или `Архив/`, без отдельной просьбы. Сохранять исходный текст, фиксировать выводы и оставшиеся задачи, обновлять ссылки и README назначения. Ожидание внедрения или утверждения не повод оставлять разобранный файл во входящих; частично разобранный файл остаётся с пометкой, что ещё нужно разобрать. Перенос не означает утверждения, канона или реализации; патчи не применять автоматически.
- Прогоны и замечания ведутся по `Документы/Прогоны/README.md`. Перед работой над шагом открыть связанные ID в `Документы/Прогоны/РЕЕСТР.md`; новые наблюдения разобрать и привязать к шагу, повторы добавлять к существующему ID. После исправления записать коммит и результат проверки по критерию. «Учтено в плане» не означает «проверено»; исторический отчёт не переписывать, причины снятия сохранять. Существенные открытые замечания учитываются в приёмке шагов 15 и 17.
- Текущий код и данные — `index.html`, `Движок/`, `Данные/`, `Сцены/`. Копию `../Сайт/Игра/Порт/` собирает скрипт; её не правят руками.
- Выгрузку диалогов в шаге 10 пересобирать `node Скрипты/собрать-диалоги.mjs`; редакторский лор хранится рядом с выгрузкой. Снимок текстов работ в шаге 5 собирает `Тесты/тексты-работ-в-md.mjs`.
- После правки следовать обязательным проверкам и публикации из порядка работы. Известные ошибки проверок перечислены в кратком состоянии: не объявлять весь набор зелёным, если они остаются.
- При изменении путей обновлять ссылки, генераторы и проверки. При изменении структуры обновлять карту; при завершении этапа или перед переходом в новый чат — краткое состояние и README затронутого шага. Не переписывать исторические отчёты как текущий статус.
- Содержательные изменения сохранять через `git add -A`, осмысленный commit и push. При отклонении push — rebase и повторная проверка.
