# Прогоны игры

Здесь сохраняются впечатления от игры, их разбор и задачи разработке. Отчёт описывает конкретную попытку на конкретной версии; текущий статус замечаний хранится только в [реестре](РЕЕСТР.md). [Шаблон](ШАБЛОН_ПРОГОНА.md) нужен для следующего прогона.

Это первый отчёт в новой системе. Старые тесты и отчёты разработки не перенумеровываются и не считаются автоматически занесёнными сюда.

## Цикл работы

1. **Прогон.** Записать дату, адрес/сборку, коммит, начало, цель, условия и точку остановки. Играть через интерфейс; отдельно указать, читал ли игрок код, план или подсказки. Записывать ожидание, действие и результат; сохранять важные скриншоты/экспорт сейва рядом с отчётом. Не опираться на временные файлы браузера.
2. **Фидбек.** Сохранить маршрут, трудности и то, что понравилось. Отличать наблюдение от объяснения причины. Прерванная сессия или отсутствие финалов в ранней сборке не доказывают непроходимость готовой игры.
3. **Разбор.** Сверить замечания с текущей игрой и планом. Определить: ошибка работающей механики/текста; недописанная часть шага; гипотеза баланса; вопрос авторского решения; либо снятое замечание. Исправление ошибки не требует ожидать окончания всего плана.
4. **Задачи.** Новое замечание получает постоянный ID вида PR001-01. Если причина уже есть в реестре, добавить источник и повторяемость к существующему ID. В карточке обязательны задача, ведущий шаг, связанные шаги, приоритет и проверяемый критерий. В оба плана и README ведущего шага добавляется ссылка на ID. Полные описания и статусы не копируются в планы.
5. **Исправление.** Перед работой над шагом открыть его связанные ID. Менять только относящиеся к задаче замечания, фиксировать коммит и проверку. Новые механики не закрывают старые замечания автоматически: проверить именно сценарий игрока.
6. **Повторная проверка.** Проверить затронутый путь на исправленной сборке. Для интерфейса, понятности и текста нужна игра через интерфейс; для механической ошибки — также подходящая проверка логики. Обновить статус, дату, версию и результат. Полный новый прогон нужен при изменениях маршрута/баланса; небольшое исправление можно проверить локально и записать в карточку.

## Статусы и приоритеты

| Статус | Что означает |
|---|---|
| Открыто | Есть конкретная задача в существующей игре; ещё не исправлена |
| Запланировано | Задача зависит от указанного будущего шага; критерий уже записан |
| Требует решения | До реализации нужно определить правило; варианты и вопрос указаны |
| В работе | Исполнитель взял задачу; записаны имя/чат и дата |
| Исправлено, ждёт проверки | Реализация есть, но сценарий игрока ещё не проверен; указан коммит |
| Проверено | Критерий выполнен; записаны версия, дата, способ и результат проверки |
| Снято | Проверка опровергла проблему либо решение осознанно отклонено; причина сохранена |

P1 — ломает причинность, сроки или существенный путь; P2 — мешает пониманию, выбору или отдельной истории; P3 — локальная редактура. Приоритет независим от статуса: даже важное отсутствие финала может ждать разработки целей. Это порядок разбора, а не требование срочно переписать все системы.

Срок задачи — соответствующий шаг и его приёмка. Исполнитель назначается при начале работы; ведущий шаг отвечает за результат, остальные дают зависимости. Если задача не помещается в шаг, явно перенести её с причиной в реестре и обновить ссылки. Незаметно оставлять её «на потом» нельзя.

## Условия закрытия

«Учтено в плане», «добавлен диалог» и «тесты зелёные» сами по себе не закрывают замечание. Для статуса **Проверено** нужны критерий карточки, коммит сборки, дата и результат повторения. Не писать «исправлено» только по обещанию или наличию материала ИИ.

В приёмке шага 15 все замечания первого сезона имеют результат: проверено/снято либо явное авторское решение об ограничении со ссылкой и причиной. Обязательная отсутствующая механика и открытые существенные дефекты блокируют приёмку; мелкие отложенные замечания отдельно перечисляются. Шаг 17 повторяет сверку для всей кампании и опубликованной версии.

Повторение закрытой проблемы возвращает тот же ID в Открыто со ссылкой на новый прогон. Старый результат проверки сохраняется в истории карточки. Исторический отчёт не переписывать под новую сборку; уточнения добавлять отдельным датированным разбором. Новые факты мира и авторские сюжетные решения проходят обычную процедуру проекта, а не утверждаются этим реестром.
