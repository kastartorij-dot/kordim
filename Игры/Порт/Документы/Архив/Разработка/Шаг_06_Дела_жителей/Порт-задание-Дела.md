# Порт — задание исполнителю: Дела (волна 1)

Написано 19.09.2026. Опирается на `../../Общие_Материалы/Порт-Дела-концепт.md` (полностью решённый
концепт — читать первым и целиком, здесь решения не повторяются, только
шаги). Это не один из девяти этапов §22 ГДД, а параллельная работа: движок
дел и десять побочных дел волны 1, которые не зависят ни от этапа 6
(амбиции), ни от каких-либо ещё не построенных мест. Три сюжетные цепочки

§4.4) сюда не входят — они ждут своих зависимостей (концепт §8) и получат

**Суть:** десятилетия ГДД §16 обещали, что побочные дела существуют, —
после этого задания они действительно существуют: доска в портовой
таверне, где можно взять «принеси», и десять человек/мест, где можно

основного цикла — дела необязательны, и это проверяется тестом (см.
«Проверка», п.4), а не декларируется в комментарии.

  `Движок/дела.js` или в правках `Движок/разговор.js` — вся конкретика
  (кто даёт, что нужно, кому нести) лежит в `Данные/дела.js` по id.
- **Ничего не ломать:** шесть текущих тестов (`вещи`, `память-места`,
  `прогон`, `сверка-этапа-4`, `сверка-этапа-5`, `экономика` — все в
  `Тесты/*.mjs`) проходят после каждого шага.
- **Не трогать:** `Канон/`, `Игры/Сайт/Приложение/`, `Игры/Генератор_Историй/Index.html`, существующие
  тексты диалогов синего часа/аптеки/бани (эффекты в них не переписываем,
  только добавляем новые узлы и новые эффекты рядом); ГДД — только §16 (см.
  «В конце») и одна строка в §22 (тоже «В конце»), остальное не трогать.
- **Тексты — черновик, не финал.** Пиши короткий, работающий текст по
  затравкам из `../../Общие_Материалы/Порт-Дела-концепт.md` §4 (одна-две реплики на узел
  достаточно, чтобы дело можно было пройти и проверить) и помечай
  `// ЧЕРНОВИК` там, где текст явно ждёт литературной правки. Полный проход
  по тексту — отдельным файлом `Порт-тексты-Дела.md`, отдельной сессией,
  не в этом задании.
- **Упрощение волны 1, сознательное:** статусы `предложено` и `отказано` из
  концепта §2.1/§2.5 в этом задании не задействуются — предложение темы
  игроку (кнопка вопроса у человека, кнопка на доске) само по себе и есть
  принятие; отдельного экрана подтверждения не делаем. Схема состояния всё

  1 не многошаговое, и эффект `дело_шаг` в `Движок/разговор.js` в этом
  задании **не заводится** — понадобится, когда появится первое дело,

**`Данные/дела.js`** — новый файл, реестр `ДЕЛА` (объект по id, как

```js
export const ДЕЛА = {
  yashik_ne_po_opisi: {
    имя: 'Ящик не по описи',
    тип: 'принеси',
    источник: { доска: 'таверна' },      // откуда доступно: доска места, ИЛИ { человек, место }
    завершение: { событие: 'торговый' }, // где и как сдаётся: район для «событий»
    срок: 1,                              // дней с момента принять(); null — без срока
    награда: { гроши: 15, фракция: { ножи: 1 } },
    провал: { тень: 1 },                  // применяется мягко, см. Движок/дела.js
```

## Шаг 2. Движок дел (`Движок/дела.js`)

Новый файл, без DOM, без имён:

- `доступныеДела(S, { источник, район } = {})` — из `ДЕЛА` те, у кого
  ещё нет записи в `S.мир.дела` (или есть, но статус `просрочено`/
  `провалено`/`отказано` — они не предлагаются повторно, дела одноразовые),
  и `источник`/`район` при передаче фильтруют по полю `источник` записи.
- `принять(S, id)` — `S.мир.дела[id] = { статус: 'активно', шаг: 0, начато: S.мир.день, срок_до: (д.срок != null ? S.мир.день + д.срок : null), данные: {} }`.
- `завершить(S, id)` — если статус не `активно`, ничего не делает (защита
  от повторного клика/устаревшего списка, тот же паттерн, что и везде в
  `действия.js`/`разговор.js`); иначе статус → `готово`, применяет
  `награда`: `гроши` — как в `Движок/разговор.js` `применить()`;
  `фракция` — `S.мир.фракции[к] = зажать(-3, 3, (S.мир.фракции[к]??0) + N)`
  (первый эффект в игре, который вообще пишет в `S.мир.фракции` — сверено,
  сейчас их только читают); `репутация` — так же, `зажать(-3, 3, ...)`;
  `тема` — через `датьТему` из `Движок/знание.js`; `распол` — через
  существующий помощник добавления расположения в `разговор.js` (если он
  не экспортирован — экспортировать `добавитьРаспол` оттуда, не дублировать
  логику зажатия −2…4). Пишет строку в `S.мир.журналДня`.
- `провалить(S, id, причина)` — статус → `провалено` (причина
  `'подведено'`) либо `просрочено` (причина `'срок'`); применяет `провал`
  теми же правилами, что `завершить` применяет `награда`; пишет строку.
- `проверитьСроки(S, итог)` — для всех `id` в `S.мир.дела` со статусом
  `активно` и `срок_до !== null && срок_до <= S.мир.день`: `провалить(S, id, 'срок')`,
  и строку — не в `S.мир.журналДня` (день уже кончился), а в `итог.причины`
  (тот же массив, куда `применитьТело` пишет причины тела, — параметр
  `итог` передаётся вызывающим кодом, см. шаг 4).

## Шаг 4. Срок — проверка на смене дня

**`Движок/время.js`, функция `закончитьДень(S, сон)`** — импортировать
`проверитьСроки` из `Движок/дела.js`; вызвать сразу после
`применитьТело(S, сон, итог)`, до `S.мир.день += 1`:

```js
применитьТело(S, сон, итог);
проверитьСроки(S, итог);
S.мир.конецДня = итог;
```

Порядок важен: `проверитьСроки` должен видеть ещё «сегодняшний»
`S.мир.день`, чтобы `срок_до <= S.мир.день` считался по дню, который
заканчивается, а не по завтрашнему.
