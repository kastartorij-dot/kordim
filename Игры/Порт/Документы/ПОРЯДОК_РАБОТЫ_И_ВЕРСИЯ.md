# Порядок работы и версия игры

Рабочая папка ПОРТа — `Игры/Порт/` в корне репозитория `kordim`.

`Игры/Порт/` — единственный источник игры. Внутри него лежат код, данные, тесты, документы и исходные изображения.

`Игры/Сайт/Игра/Порт/` — не вторая рабочая версия, а автоматически собранная копия для сайта. Её не редактируют вручную. Она создаётся командой `npm run publish` из исходников `Игры/Порт/`.

Отдельная LLM-игра «Кордим: Хроники» восстановлена в `Игры/Генератор_Историй/`. Её публикация собирается в `Игры/Сайт/Игра/Истории/`.

## Как версии совпадают

Версия игры — один коммит ветки `main` в GitHub `kastartorij-dot/kordim`. В коммит с изменениями игры входят исходники `Игры/Порт/` и результат сборки `Игры/Сайт/Игра/Порт/`. После этого выполняется один `git push origin main`.

Номер сохранения (`12` сейчас) — совместимость данных, а не номер выпуска. `0.1.1` в Приложение_Для_ПК — версия Windows-оболочки, а не всей игры.

## Порядок каждой сессии

Перед началом:

```powershell
git switch main
git pull --rebase origin main
```

При работе над шагом сверить его ID в [реестре замечаний прогонов](Прогоны/РЕЕСТР.md). Новый фидбек оформлять по [процессу](Прогоны/README.md): отчёт → разбор → задача со шагом и критерием → исправление → повторная проверка. После исправления записать коммит и результат; перед приёмкой шага сверить связанные задачи.

После правки:

```powershell
npm run publish-all
npm run check
Get-ChildItem Тесты/*.mjs | ForEach-Object { node $_.FullName; if ($LASTEXITCODE -ne 0) { throw "Провал: $($_.Name)" } }
git status
git add -A
git commit -m "понятное описание изменения"
git push origin main
```

Если push отклонён, выполнить `git pull --rebase origin main`, снова `npm run publish`, `npm run check`, затем push.

Статус читается так: «в игре» означает код и проверку; «частично» — работает только первый слой; «материал» — документ, ZIP или картинка без подключения; «не начато» — только план.
