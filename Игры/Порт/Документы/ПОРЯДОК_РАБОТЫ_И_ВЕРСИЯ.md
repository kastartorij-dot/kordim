# Порядок работы и версия игры

Рабочая папка ПОРТа — `Игры/Порт/` в корне репозитория `kordim`.

`Игры/Порт/` — единственный источник игры. Внутри него лежат код, данные, тесты, документы и исходные изображения.

`Игры/Сайт/Игра/Порт/` — не вторая рабочая версия, а автоматически собранная копия для сайта. Её не редактируют вручную. Она создаётся командой `npm run publish` из исходников `Игры/Порт/`.

Отдельная LLM-игра «Кордим: Хроники» восстановлена в `Игры/Генератор_Историй/`. Её публикация собирается в `Игры/Сайт/Игра/Истории/`.

## Как версии совпадают

Версия игры — один коммит ветки `main` в GitHub `kastartorij-dot/kordim`. В коммит с изменениями игры входят исходники `Игры/Порт/` и результат сборки `Игры/Сайт/Игра/Порт/`. После этого выполняется один `git push origin main`.

Номер сохранения (`14` сейчас) — совместимость данных, а не номер выпуска. `0.1.1` в Приложение_Для_ПК — версия Windows-оболочки, а не всей игры.

## Порядок каждой сессии

Перед началом:

```powershell
git switch main
git pull --rebase origin main
```

При работе над шагом сверить его ID в [реестре замечаний прогонов](Прогоны/РЕЕСТР.md). Новый фидбек оформлять по [процессу](Прогоны/README.md): отчёт → разбор → задача со шагом и критерием → исправление → повторная проверка. После исправления записать коммит и результат; перед приёмкой шага сверить связанные задачи.

### Проверки по завершении пачки (решение автора 15.11.2026)

Сначала закончить связанную пачку работы, затем проверить её результат. Не запускать полный набор после каждого файла, промежуточной правки или исправления документации. Во время работы повторять только проверку, которая нужна для конкретной ошибки; после исправления повторять упавшую проверку и затронутые сценарии.

- Портреты и фоны: проверить пути, прозрачность, вес файлов и показ в игре на нужных экранах; затем сборку. Тесты экономики, сюжетных маршрутов и сохранений для замены картинки не нужны.
- Тексты и локальный интерфейс: связанные проверки и просмотр затронутого места. Для правки только рабочих документов — проверить diff и ссылки, без запуска игры и общего набора.
- Общая механика (время, деньги, сохранения, сроки), объединение крупных изменений или сдача этапа: один общий прогон после завершения и объединения пачек. Не дублировать его у каждого агента и затем ещё раз у Шефа, если состав проверяемого кода не изменился.

Номер «67» не норматив: на 15.11 в `Тесты/` лежит 67 файлов `.mjs`, включая генератор `тексты-работ-в-md.mjs`. Это 66 тестовых скриптов с множеством внутренних проверок и один служебный скрипт. Генератор не запускать как самостоятельный тест: нужную сверку его вывода уже выполняет `шаг5.mjs`. В отчёте называть реально проверенные части и найденные ошибки; не подавать количество запущенных файлов как доказательство качества игры.

После законченной пачки, затрагивающей игру (сначала связанные проверки по правилам выше):

```powershell
npm run publish-all
npm run check
git status
git add -A
git commit -m "понятное описание изменения"
git push origin main
```

Когда по правилам выше нужен общий прогон, выполнить один раз перед фиксацией проверенного результата:

```powershell
Get-ChildItem Тесты/*.mjs | Where-Object { $_.Name -ne 'тексты-работ-в-md.mjs' } | ForEach-Object { node $_.FullName; if ($LASTEXITCODE -ne 0) { throw "Провал: $($_.Name)" } }
```

Если push отклонён, выполнить `git pull --rebase origin main`, снова `npm run publish`, `npm run check`, затем push.

Статус читается так: «в игре» означает код и проверку; «частично» — работает только первый слой; «материал» — документ, ZIP или картинка без подключения; «не начато» — только план.
